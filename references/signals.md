# 六类信号定义

| 信号 | 对应 skill 部件 | 一句话定义 |
|------|----------------|-----------|
| goal      | 目标 / 成功判据 | 什么叫做完 |
| trigger   | description     | 什么时候该用这个 skill |
| actions   | SOP 主体        | 按序执行的动作序列 |
| decisions | 分支判断        | 需要根据条件选择的点 |
| pitfalls  | 硬约束          | 踩过的坑及其修正 |
| assets    | scripts/assets  | 沉淀过程中产出的可复用文件 |

## 逐项抽取标准

### goal 目标 / 成功判据

- 正例：用户开场意图、「目标是…」「验收标准是…」「做完了意味着…」
- 反例：过程中的子任务描述、闲聊
- 置信度：出现在轨迹前 60 行 + 含意图词 → 0.7；仅 1~3 条进入骨架

### trigger 触发条件

- 正例：「当…时」「每当…」「如果遇到…」「适用于…」
- 反例：一次性的事实陈述（「今天遇到了…」不带复用语义）
- 首条 trigger 直接参与生成 description

### actions 动作序列

- 正例：代码块中实际执行过的 shell 命令、被验证有效的操作步骤
- 反例：失败的命令、试探性命令（无后续修正则丢弃）
- 保持执行顺序，逐条编号进入 SOP

### decisions 决策点

- 正例：「如果 X 则 Y，否则 Z」「先检查 A 再决定 B」「根据 X 选择…」
- 反例：已经确定无疑的直线流程（无分支）
- 写成显式分支条件，进入「决策点」章节

### pitfalls 坑与修正

- 正例：报错信息、失败尝试、用户纠正、「注意：…」「不要…」
- 必须配对：坑 + 修正（fix），只有坑没有修正的条目置信度降级
- 直接进入「硬约束」章节，用「禁止/必须」句式固化

### assets 可复用资产

- 正例：过程中创建/修改且可复用的文件（脚本、配置、模板）
- 反例：临时文件、一次性产物（构建产物、lock 文件）
- 记录相对路径，进入「可复用资产」章节

## 分流规则（routing_hint）

```
trigger 存在 且 actions >= 3        -> skill
（goal | pitfalls）存在 且有动作    -> memory
其余                                -> skip
```
